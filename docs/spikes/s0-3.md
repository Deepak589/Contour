## Tags (mechanical)

- `multi_hop`: gold spans ≥ 2 files.
- `explicit_path`: the issue text contains a gold path, the path without a leading `src/` or `lib/`, or its dotted module
  (only when the module has ≥ 2 parts, so `utils` alone doesn't count).
- `paraphrase`: no gold symbol name appears as a whole word in the issue text. Names shorter than 4 characters and
  dunders (`__init__`) are ignored because they match by chance.
  - czlll: symbols from `edit_functions` (exact).
  - SWE-bench-Live: symbols from diff hunk headers, which name the enclosing `def`/`class` near the hunk. **Approximate**;
    exact function gold comes from base-commit parsing in S2-1.
- `repo_size`: needs node counts from the S2-4 index build. Not computed here.
- **Hand check:** 10 random tasks (`--hand-check 10`). Path and symbol hits matched the gold in all 10. It surfaced the
  short-name problem (`user`, `of`, `__init__`), which the length and dunder rule now handles.

## Stale eligibility (k = 20, sample)

A task is eligible when at least one gold file changed in the 20 first-parent commits before its base commit
(`git diff --name-only <base>~20 <base>`). Bare clones (`--filter=blob:none`) in `EVALH_CACHE`. Sample: the 3 largest
test-pool repos plus 7 random repos with ≥ 5 tasks (seed 0). Every base commit was found; no history was too short.
