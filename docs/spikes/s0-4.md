## Findings

1. **`node:sqlite` needs Node ≥ 22.13.** On `node:22.12` (the `devEngines` minimum), `init` fails:
   `No such built-in module: node:sqlite`. It's still flag-gated in 22.12. Pinned base is 22.23.
2. **Default `tools/list` advertises only `codegraph_explore`** (`src/mcp/tools.ts:2023-2034`, `DEFAULT_MCP_TOOLS`).
   `search`, `callers`, `callees`, `impact`, `node`, `files` and `status` are hidden but still answer if called.
   `CODEGRAPH_MCP_TOOLS=explore,search,...` re-lists them. **Design decision needed (fairness):** does F0 use the
   upstream default (explore only) or the full set? The server instructions also steer the agent to explore only.
3. **`codegraph_explore` output is large.** About 21–25K chars per call on Django (the description says the cap is ~13–24K chars by project size). That's roughly 6K tokens per call. It feeds T_loc directly.
4. **A writable mount changes the DB even when nothing changed.** Fresh index, fresh checkout, `--no-watch`:
   SHA changes in both modes. A SHA check can only pass with a read-only DB.
5. **A plain `:ro` mount of the checkout breaks both modes.** Upstream writes `.codegraph/writer.pid.*.tmp` before it opens anything:
   - direct: `Failed to start server: EROFS ... writer.pid.13.tmp`, no `initialize` reply (hangs until timeout).
   - daemon: handshake OK, then every tool call returns `-32603 EROFS ...` ("serving in-process (degraded)").
   The `index.ts:146-149` read-only fallback is never reached here, because the lock write fails first.
6. **Frozen route (works, unmodified upstream):**
   ```
   -v <tree>:/repo:ro
   --tmpfs /repo/.codegraph
   -v <tree>/.codegraph/codegraph.db:/repo/.codegraph/codegraph.db:ro
   ```
   Lock files land in tmpfs. Catch-up sync logs `Catch-up sync failed for /repo: attempt to write a readonly database`
   and the server keeps serving. On a stale tree, `codegraph_status` reports the drift (14 added, 450 modified,
   33 removed), so the index really is stale and stays stale. This matches design §4 "read-only checkout and index mounts".
7. **Writable + stale = real catch-up.** 43 s wall time, 3.5 s tool latency while reconcile runs in the background
   (`#905` gate, 3000 ms), DB rewritten. Confirms design H4 note: F0 in normal use is not stale.
8. **Killing the `docker run` client does not stop the container.** A leftover writable container kept writing
   `-shm`/`-wal` into the next run's index and faked a failure. The harness must `--name` each container and
   `docker rm -f` it on exit (done in `scripts/mcp_smoke.py`). This applies to S1-5 container lifecycle too.

## Reproduce (macOS or WSL2)

WSL2: keep trees on the Linux filesystem (`~/evalh-cache`), not `/mnt/c`. It's slower there, and CodeGraph has
Windows/WSL shared-index checks (`src/db/wsl-shared-index.ts`). Docker Desktop with WSL integration, or Docker Engine inside WSL.

```bash
docker build -t evalh/codegraph:f72c9d2 docker/codegraph
docker run --rm evalh/codegraph:f72c9d2 version                     # 1.6.2

C=${EVALH_CACHE:-$HOME/evalh-cache}
git clone https://github.com/django/django.git $C/repos/django
git -C $C/repos/django checkout 1860f0a3f4                           # pin for comparable numbers
T=$C/trees/django-1860f0a3f4; mkdir -p $T
git -C $C/repos/django archive HEAD | tar -x -C $T                   # clean tree, no .git (rule 7)
time docker run --rm --network none -v $T:/repo evalh/codegraph:f72c9d2 init -y /repo
cp -R $T/.codegraph $C/django-1860f0a3f4.codegraph.pristine          # restore this before each run

uv run python scripts/mcp_smoke.py $T --frozen --direct              # exit 0 = MCP ok + DB unchanged
uv run python scripts/mcp_smoke.py $T --frozen
uv run python scripts/mcp_smoke.py $T --ro --direct --timeout 20     # expected to fail (EROFS)

S=$C/trees/django-stale; mkdir -p $S
git -C $C/repos/django archive HEAD~300 | tar -x -C $S
cp -R $C/django-1860f0a3f4.codegraph.pristine $S/.codegraph
uv run python scripts/mcp_smoke.py $S --frozen --direct              # the S0-4 acceptance run
```

## Open / not verified

- **amd64 natively (teammate, WSL2):** build, index time, and the frozen matrix. Index time on WSL is what §13 compute uses.
- Index timing on Linux (bare metal) is not measured. Docker Desktop's VM on macOS adds file-sharing overhead.
- Whether direct or daemon mode should be F0's mode. Both pass. Direct is simpler (one process, no socket).
- F0 tool surface (finding 2) needs a team decision before G1.
